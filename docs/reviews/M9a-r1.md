Hinweise (nicht blockierend, bis spätestens M9b/M9d erledigen):
1. Spuren in Stacktraces: `HttpGate::send(array $headers, ?array $form)` und `OAuthService::token(array $form)` tragen kein `#[\SensitiveParameter]`. Wirft dort etwas anderes als `GateException` (Error in Antwortverarbeitung), loggt NC den Trace mit `client_secret`, `code`, `refresh_token` bzw. `Authorization: Bearer …` als Argument (Docker-PHP ohne php.ini: `zend.exception_ignore_args=Off`). Plan §6 „nie Token/Secret/Code in Logs“. Fix: beide Parameter markieren.
2. Größengrenze „beim Lesen abbrechen“ (§6) greift nicht wirklich: `ClientService::newClient()` nutzt fest `CurlHandler`, `stream => true` wird damit nicht an den StreamHandler geleitet; curl lädt den ganzen (dekodierten) Body nach `php://temp`, erst danach prüft `HttpGate::read` die Grenze. Für JSON ≤ 4 MiB unkritisch, für Ressourcen ≤ 100 MiB in M9d per `progress`-Option oder `sink` mit Abbruch lösen. (Vorteil: curl dekodiert auch `br`, das NC bei brotli-fähigem curl anbietet.)
3. Done 14 / §3 Nachzählen „kleinste id gewinnt“: Auf pgsql/MariaDB wird die id vor dem Commit vergeben; theoretisch kann die größere id zuerst committen und nachzählen, bevor die kleinere sichtbar ist → zwei offene Zeilen. Fenster Mikrosekunden, Folge harmlos (nächstes connect ersetzt beide auth/select). Nur dokumentieren.
4. Spalte `cursor` ist in MariaDB/MySQL reserviert. DBAL/QueryBuilder quoten, also kein Fehler; in M9b keine Roh-SQL-Strings mit `cursor` (auch nicht in `check-forbidden-sql`-Ausnahmen).
5. Done 6 „Log-Suche in `nextcloud.log` 0 Treffer“: PHPUnit prüft nur den Prozess-Logger (`OAuthTest` Z. 392). Lead sollte im Testnachweis eine echte `nextcloud.log`-Suche nach Mock-Token/Code/Secret nach dem msmock-Lauf verlangen.
6. Plan §9 nennt den Mock „Node, ohne Abhängigkeiten“; umgesetzt ist PHP/Apache aus dem NC-Image. Durch ADR-0020-Nachtrag gedeckt; Plan-Text bei M9e angleichen.
7. Versionssprung 0.9.0 → 0.9.1 mit Migration und CHANGELOG-Eintrag: in Ordnung.
